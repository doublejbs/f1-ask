# 29. 타이어 전략 — 사용한 타이어 + 남은 타이어 경우의 수

## 배경

docs/27(주말 컨텍스트)은 프랙티스·퀄리 결과를 다루되 **타이어/스틴트 분석은 범위 밖**으로
뒀다. 사용자 요청으로 드라이버별 **타이어 전략**(그동안 쓴 타이어 + 남은 타이어)을 상세
시트에 노출한다.

## 데이터 현실 — 정직하게 못박는다

| 항목 | OpenF1 | 결론 |
|---|---|---|
| 세션별 사용 compound | ✅ `stints`(compound·`tyre_age_at_start`) | 표시 가능 |
| 남은 세트 수(잔여) | ❌ 할당·세트 ID 없음 | **정확히는 불가** |

**남은 타이어는 규정 기반 "경우의 수"로만 낼 수 있다.** OpenF1 스틴트엔 어떤 세트를 썼는지
식별자가 없고, 반납한 컴파운드는 팀 선택이라 잔여 구성이 하나로 확정되지 않는다. 그래서
할당·반납 규정만으로 **가능한 구성 전체**를 보여 준다.

### 할당·반납 규정 (사용자 제공)

| | 할당 | 반납 |
|---|---|---|
| 일반 주말 | H2 · M3 · S8 (13) | FP1 후 2 · FP2 후 2 · FP3 후 2 → 7세트 잔여 |
| 스프린트 주말 | H2 · M4 · S6 (12) | FP1 후 1 · 스프린트 후 1 · 퀄리 후 3 → 7세트 잔여 |

## 설계

### 결정론적 코어 — `TireAllocation`

- `WeekendFormat`(Conventional·Sprint)별 `DRY_TIRE_ALLOCATION`·`TIRE_RETURN_SCHEDULE`.
- `remainingSetCount(format, returnedCount)` — 잔여 총수(정확히 하나).
- `remainingTirePossibilities(format, returnedCount)` — 합=잔여, 각 컴파운드≤할당인 **모든
  구성**. 반납 컴파운드가 팀 선택이라 이 목록의 하나가 실제 보유분이다(어느 것인지 모른다).
- `summarizeRemainingRanges(...)` — 컴파운드별 min–max 로 압축(표시용).
- LLM 을 쓰지 않는다 — 전부 산수. 도메인 단위 테스트로 고정.

### 사용한 타이어 — 스틴트 이력

- `StintContextSummary.usedCompounds: { compound; startedNew }[]` 를 추가한다. 워커가
  `stints` 를 시작 순서대로 담고, `startedNew = tyre_age_at_start === 0`(신품/중고)로 표기.
- 스냅샷 스키마에 필드를 더한다. mock·옛 recording 엔 contextSummary 가 없어 "데이터 없음"
  으로 뜨고, **라이브 워커에서만 채워진다**(추월 예측 신뢰도와 같은 성질).

### UI — 드라이버 상세 시트

- `DriverTireStrategyView`: 「사용한 타이어(이번 세션)」 compound 칩(신품/중고) + 「남은 세트」
  보유 수·경우의 수·컴파운드별 범위(할당 대비).
- **계산 한계를 문구로 명시**한다 — 일반 주말 규정 기준, 반납 컴파운드는 팀 선택(경우의 수),
  퀄리·프랙티스 사용분 미반영.

## 개정 — Archive 주말 타이어 (구현)

「기록」 상세에 **주말 타이어 격자**를 더했다 — 드라이버 × 세션(FP1/FP2/FP3/SQ/SPR/Q/R)으로
각 세션에서 쓴 compound 를 보여 준다.

- **온디맨드 fetch**: `loadWeekendTires(meetingKey)` 가 `sessions`·`stints`·`drivers` 를
  meeting_key 로 3요청 받아 `buildWeekendTireUsage` 로 정규화한다. 아카이브와 같은
  `unstable_cache` 로 조립 결과만 캐시(`getWeekendTires`).
- **세션 지목·정렬**: 미팅의 실제 세션 목록을 date_start 로 정렬하고 session_name 으로
  분류한다(고정 enum 아님). **주말 형식은 자동 판정**한다 — "Sprint" 세션이 있으면 스프린트.
- **정규화 규칙**: compound null 스틴트(확정 전 임시 행) 제외, 취소 세션 제외, 로스터
  조인으로 코드 채움(FP1 루키 포함), 스틴트 lap_start 순서 유지.
- 격자 셀은 그 세션의 **구별되는** compound 비드로 압축, 미주행 세션은 `–`.

## 범위 밖 (이후 단계)

- **경우의 수 축소** — 관측된 세션별 사용분으로 드라이버 상세의 남은 타이어 가능성을 좁히기.
  지금은 아카이브 격자(사용 이력)와 상세 경우의 수(규정)가 분리돼 있다.
- **FIA 타이어 할당 실데이터** — 확보되면 경우의 수를 실제 보유분으로 대체.
- 드라이버 상세의 주말 형식도 자동 판정 적용(지금 상세는 일반 주말 고정, 아카이브 격자만
  자동 판정).

## 수용 기준

1. `TireAllocation` 이 두 주말 형식의 할당·반납을 규정대로 계산한다(일반 6반납·스프린트 5반납,
   둘 다 7세트 잔여). 도메인 테스트로 고정.
2. 남은 타이어가 **경우의 수**로 표시된다 — 보유 총수(정확) + 가능한 구성 개수 + 컴파운드별
   범위. 반납 컴파운드가 팀 선택이라는 한계가 문구로 드러난다.
3. `usedCompounds` 가 스틴트 이력을 시작 순서·신품/중고로 담고, 실데이터(벨기에 GP)로 고정된다.
4. 드라이버 상세 시트에 타이어 전략 섹션이 뜬다. 스틴트 데이터가 없으면 "데이터 없음"으로,
   경우의 수는 규정만으로 항상 표시된다.
5. i18n en/ko/ja. "남은 타이어"가 정확한 잔여로 오해되지 않게 규정 기반 추정임을 명시.
